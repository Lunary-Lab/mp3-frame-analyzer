# Conformance, format coverage and evidence matrix

This is a **capability and test checklist**, not a claim of certified ISO conformance or a list of employer-imposed acceptance requirements. The [assessment-only checklist](../assessment-brief.md#appendix-project-interpretation-not-assignment-text) takes precedence: metadata policies, the configurable 50 MiB default and raw upload include project choices. Applicable authority: [source register](README.md). Source-of-truth for what the assignment demands: [original brief](../assessment-brief.md). The [count contract](../frame-count-contract.md) records the owner-selected HTTP default and the dated audio-frame/sample clarification. Entries describe implementation and its limits, not proof from an exhaustive conformance run. The inclusive 320 kbps free-format interpretation follows the detailed maximum-rate rule and arithmetic; the definition's wording distinction remains documented.

Legend: **Required** = assessment's format; **Supported** = implemented structural handling; **Limited** = implemented with documented restriction; **Policy** = stricter or extended application choice; **Out of scope** = not required for assignment; **Open** = unresolved external interpretation; **Confirmed** = dated evaluator clarification of the stated requirement and sample expectation, not a full conformance result.

## Error distinctions and executable coverage

See the [input classification matrix](http-api.md#supported-unsupported-and-malformed-input) for supported
geometry, recognized out-of-scope identifiers, reserved/forbidden identifiers,
truncation, unknown future ID3 versions and exact raw/multipart HTTP errors.
Reserved MPEG version/layer identifiers and forbidden ID3 `0xff` version bytes
are malformed (422), not a genuinely identified unsupported format (415).
The matrix distinguishes encoder-produced fixtures from header-only probes;
rejection does not validate another codec's payload or frame geometry.

Free-format envelope regressions are in `tests/mp3/free-format-rate-bound.test.ts`;
`tests/mp3/short-free-format-dead-end.test.ts` covers the EOF-only, single-configuration
root fallback for dead-end ancillary headers, impossible alternate side fields,
exact alternate main-data capacity, crossing complete layouts and
unchanged metadata/changed-rate/indexed-header conservatism. A complete layout remains subject
to the documented inference limits; this is not a full conformance proof.
`tests/free-format-rate-upload.test.ts` verifies the same count/error contract in
both upload modes and every count-option setting.

## Rules for tests and claims

1. A **valid structural test** needs an independent frame-offset/count oracle (synthetic manifest) or an independently produced encoder corpus checked by another implementation. A single decoder's decoded frame count need not equal physical frames. Construction offsets do not establish uniqueness for competing free-format layouts; such tests must assert ambiguity.
2. For each supported bitrate/rate/mode/CRC/padding combination, test exact counts and chunk-boundary invariance. For free-format, include variable padding, genuinely in-scope competing candidates, below-table rates that fit the mandatory prefix, both base and physical upper bounds, maximum-base padding rejection at 32/48 kHz, very short streams, and truncation. Extension-only ancillary candidates must not veto supported layouts.
3. The generic binary Jazzer target tests crash-freedom and consistent results across chunkings; it is **not** an oracle of positive counts. The independent construction target covers indexed and free-format streams, per-frame padding/CRC/channel variation, and optional initial encoder headers with known offsets and both count policies. Its known-count free-format payloads exclude accidental sync bytes to avoid ambiguous oracle labels; these structural fixtures do not establish full decoded-audio validity.
4. A test or lint score, even 100% coverage, does **not** demonstrate conformance to all MPEG bitstream/decoder requirements. The [full-parser mutation gate](../mutation-review.md) covers every module, including `free-format.ts`, `encoder-frame.ts` and traversal; keep it at 100% adjusted when changing them.
5. Document violations of _format_ rules separately from deliberate _application_ limitations. For example, ambiguity-driven free-format rejection or a deliberate metadata resource cap does not make such a stream non-MPEG-1 Layer III.
6. Any change to default `frameCount` semantics requires explicit owner decision and simultaneous revisions of assessment sample tests, API docs and count contract. Never silently use `ffprobe nb_read_frames` or `MediaInfo FrameCount` as a physical count.
