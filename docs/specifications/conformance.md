# Conformance, format coverage and evidence matrix

This is a **capability and test checklist**, not a claim of certified ISO conformance or a list of employer-imposed acceptance requirements. The [assessment-only checklist](assessment-scope.md) takes precedence: most metadata, 50 MiB, raw upload and 321–640 kbps entries below are project choices. Applicable authority: [source register](README.md). Source-of-truth for what the assignment demands: [original brief](../assessment-brief.md). The [count contract](../frame-count-contract.md) records the owner-selected HTTP default and unconfirmed evaluator intent. The statuses below describe the code inspected on **2026-10-24**, not proof from a fresh exhaustive CI run.

Legend: **Required** = assessment's format; **Supported** = implemented structural handling; **Limited** = implemented with documented restriction; **Policy** = stricter or extended application choice; **Out of scope** = not required for assignment; **Open** = unresolved external interpretation.

## Rules for tests and claims

1. A **valid structural test** needs an independent frame-offset/count oracle (synthetic manifest) or an independently produced encoder corpus checked by another implementation. A single decoder's decoded frame count need not equal physical frames.
2. For each supported bitrate/rate/mode/CRC/padding combination, test exact counts and chunk-boundary invariance. For free-format, include variable padding, competing sync candidates, unusual valid integer rates, 640 kbps at 32 kHz, very short streams, and truncation.
3. The generic binary Jazzer target tests crash-freedom and consistent results across chunkings; it is **not** an oracle of positive counts. The independent construction target covers indexed and free-format streams, per-frame padding/CRC/channel variation, and optional initial encoder headers with known offsets and both count policies. Its known-count free-format payloads exclude accidental sync bytes to avoid ambiguous oracle labels; these structural fixtures do not establish full decoded-audio validity.
4. A test or lint score, even 100% coverage, does **not** demonstrate conformance to all MPEG bitstream/decoder requirements. The [full-parser mutation gate](../mutation-review.md) covers every module, including `free-format.ts`, `vbr-header.ts` and traversal; keep it at 100% adjusted when changing them.
5. Document violations of _format_ rules separately from deliberate _application_ limitations. For example, ambiguity-driven short free-format rejection or unsupported in-stream ID3 does not make such a stream non-MPEG-1 Layer III.
6. Any change to default `frameCount` semantics requires explicit owner decision and simultaneous revisions of assessment sample tests, API docs and count contract. Never silently use `ffprobe nb_read_frames` or `MediaInfo FrameCount` as a physical count.
