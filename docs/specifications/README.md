## Scope separation (essential for AI coding agents)

1. **The assignment is narrower than generic `audio/mpeg`.** RFC 3003 can describe a stream with interspersed non-MPEG bytes; the endpoint intentionally accepts a stricter sequence: supported leading metadata, complete MPEG-1 Layer III frames and supported trailing metadata, without arbitrary junk resynchronization. That is an **application policy**, not a claim that RFC 3003 prohibits other layouts.
2. **Metadata tags are independent of the MPEG audio coding standard.** Implement only byte-boundary handling needed for accurate counts. ID3 text encodings, embedded artwork, replay gain, extended headers, ID3 frame content and CRC fields do **not** need full interpretation.
3. **Xing/Info/LAME and VBRI are de facto encoder headers, not additional MPEG layers.** They can inhabit MPEG frames. The owner selected HTTP exclusion of one recognized initial header for omitted/`false`; explicit `true` and direct parser calls with no option count physical frames. These are project policies, not ISO requirements. The evaluator confirmed audio-frame counting and sample result 6089 on 2026-10-26; implementation details beyond that clarification remain distinct. See the [count contract](../frame-count-contract.md).
4. **Free-format is not MPEG-2 or an invalid bitrate.** Index zero is a valid MPEG-1 Layer III encoding choice with no table-derived frame length. Its per-sample-rate candidate limit is separate from the fixed observation budget. A decoder's size-search heuristic or minimum support requirement does not establish a normative upper limit; LAME extensions cannot compete with in-scope candidates.
5. **Full ISO Layer III bitstream conformance would require decoding-side checks** (side information, bit reservoir, Huffman, CRC, etc.). This assessment explicitly requests logical _frame counting_. Do not change the project into an audio decoder.

The [successive-sequence policy](successive-sequences.md) separately records ISO sequence invariants, RFC 3003 elementary-stream terminology, the MSE-specific W3C frame-combination profile and bounded project inference decisions. These are not universal unique-framing rules.

## Safe referencing practice

These Markdown files contain short **original implementation summaries**, not reproductions of the copyrighted ISO standard. The mandatory-prefix and free-format minimum-span rules reference ISO/IEC 11172-3:1993 clauses; independently constructed fixtures exercise those findings. This is not full decoder or certified bitstream conformance. The ISO public catalog verifies the identity/current status but does not supply every byte-level clause; numeric tables and bit layouts below are implementation-oriented summaries independently corroborated by [FFmpeg's MPEG header decoder](https://github.com/FFmpeg/FFmpeg/blob/c220739be57307ea821d1197ad89ff6e372180e8/libavcodec/mpegaudiodecheader.c), [mpg123's bit masks](https://github.com/libsdl-org/mpg123/blob/b6881556a0ee8f417ccc14ded553893b533ffe0c/src/libmpg123/mpeghead.h), and LAME. If a disputed conformance interpretation matters, consult the complete ISO text or ISO/IEC 11172-4 instead of asserting an invented clause number.
